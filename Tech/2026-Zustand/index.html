Zustand 🐻

작은 전역 상태 관리자 — store 자체가 hook, Provider 없음. React / RN / 바닐라 동일 API.

30초 요약

  • create() 하나로 store, useStore(s => s.조각) 선택 구독. Provider 래핑 불필요.
  • Redux와 개념 유사(불변)하되 보일러플레이트 없음. zombie child·동시성·context loss 해결.
  • 셀렉터가 곧 구독: 통째 구독 금지, 객체 묶음은 useShallow.
  • 서버 상태는 react-query 자리. zustand는 클라이언트 상태만.

최소 코드

import { create } from 'zustand'

const useBear = create((set) => ({
  bears: 0,
  increase: () => set((s) => ({ bears: s.bears + 1 })),
}))

// 이 조각이 바뀔 때만 리렌더
const bears = useBear((s) => s.bears)
주의: set은 1레벨 얕은 병합. 중첩 상태는 spread/Immer로. set(next, true) 전체교체는 액션까지 삭제.

비교표

상대차이
Redux개념 유사, Provider 필수+보일러플레이트. 대규모 규율·DevTools 생태계면 Redux
Valtiomutable(proxy) 자동최적화. "막 써도 되게"면 Valtio, 명시적이면 Zustand
Jotai원자 조합 vs 단일 store. 잘게 쪼갠 파생이면 Jotai

핵심 6

  1. 파생값은 계산: xIsNext = currentMove % 2 — 저장하면 동기화 깨짐.
  2. Slices: 큰 store는 slice로 나눠 합치기. middleware는 합친 곳에만.
  3. 액션 외부화 가능: setState 직접 호출 — hook 없이, 코드스플리팅 용이.
  4. 컴포넌트 밖 구독: getState/subscribe — 가드·유틸·백그라운드 자리.
  5. 자주 바뀌는 값: subscribe+ref transient 처리로 리렌더 없이.
  6. TS: create<State>()(...) 한 겹 더. combine이면 추론.

미들웨어 4종

  • persist — 새로고침 유지 (localStorage 등)
  • devtools — Redux DevTools 연결, 액션명 지정 가능
  • immer — 중첩 업데이트 간편
  • subscribeWithSelector — 선택 구독+이전값+즉시발화

React Native 적용

RN·웹·바닐라 동일 API. 네이티브 모듈과는 createStore(vanilla)로 공유. persist 저장소만 AsyncStorage 어댑터로 교체. 테스트는 RNTL+MSW. FSD model/ 세그먼트가 slice 자리.
