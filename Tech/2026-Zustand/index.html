30초 요약

  • create() 하나로 store, useStore(s => s.조각) 선택 구독. Provider 래핑 불필요.
  • Redux와 개념 유사(불변)하되 보일러플레이트 없음. zombie child·동시성·context loss 해결.
  • 셀렉터가 곧 구독: 통째 구독 금지, 객체 묶음은 useShallow.
  • 서버 상태는 react-query 자리. zustand는 클라이언트 상태만.

최소 코드 — store가 hook이다

import { create } from 'zustand'

const useBear = create((set) => ({
  bears: 0,
  increase: () => set((s) => ({ bears: s.bears + 1 })),
}))

// 이 조각이 바뀔 때만 리렌더
const bears = useBear((s) => s.bears)

상태+액션을 한 store에 colocate하는 게 권장. 컴포넌트는 필요한 조각만 선택한다 — 선택한 조각이 바뀔 때만 리렌더되므로, 통째로 구독하는 것(useBear())은 매 변경에 전부 다시 그리는 지름길이다.

병합 규칙 — set은 1레벨만 합친다

set은 최상위 1레벨만 얕게 병합한다. set({ bears: 5 })는 나머지(state 전체)를 유지하지만, 중첩 객체는 직접 spread해야 한다:

nested: { ...state.nested, count: state.nested.count + 1 }

깊어지면 Immer 미들웨어로 (set(produce(s => { s.a.b.c++ }))). 전체 교체는 set(next, true) — 액션까지 날아가니 주의. 액션 안에서 현재값 읽기는 get(), async 액션은 그냥 set 호출 (특별 취급 없음).

비교표 — 왜 Redux 대신인가

상대차이선택 기준
Redux개념 유사(불변). Redux는 Provider 필수 + 보일러플레이트새 프로젝트·소규모→Zustand. 대규모 규율·DevTools 생태계→Redux Toolkit
Valtiomutable(proxy) + 접근 기반 자동최적화"막 써도 되게"면 Valtio, 명시적 불변+셀렉터면 Zustand
Jotai원자(atoms) 조합 vs 단일 store잘게 쪼갠 파생 상태→Jotai, 기능 단위 store→Zustand
Recoilatom 키 + Provider 필요신규 비권장 분위기

렌더 최적화는 넷 다 수동 셀렉터가 정석이다.

핵심 7

  1. 파생값은 계산, 저장 금지: xIsNext = currentMove % 2 (공식 Tic-Tac-Toe 교훈) — 저장하면 동기화 깨짐.
  2. Slices 패턴: 큰 store는 createFishSlice+createBearSlice로 나눠 create((...a) => ({...합침})). middleware는 합친 store에만 (slice 안에 걸면 오동작).
  3. 액션 외부화 가능: store 밖에 setState 직접 호출 — hook 없이 호출 + 코드스플리팅 용이. 캡슐화 취향이면 colocation.
  4. 컴포넌트 밖 읽기/구독: getState()·setState()·subscribe() — 네비게이션 가드·유틸·백그라운드 자리. 단 Next 서버컴포넌트에서는 금지.
  5. 자주 바뀌는 값: subscribe+ref transient 처리로 리렌더 없이 (스크롤·애니메이션).
  6. 객체 선택엔 useShallow: useShallow(s => ({nuts, honey})) — 새 객체라 매번 바뀐 걸로 보이는 문제 해결.
  7. reset은 상수로: initialState 상수 + set(initialState) (로그아웃·세션초기화).

TypeScript — 커링 한 겹

타입 지정 시 커링(currying) 문법인 create<BearState>()(…) 형태로 선언한다. combine을 쓰면 interface 없이 상태·액션 추론. ExtractState로 테스트·유틸 타입 재활용. 비동기 액션도 타입 그대로 (fetchBears: () => Promise<void>).

미들웨어 4종

  • persist — 새로고침 유지. { name: '저장키' } + 저장소 교체 가능.
  • devtools — Redux DevTools 연결. set 3번째 인자로 액션명 지정.
  • immer — 중첩 업데이트 간편 (zustand/middleware/immer).
  • subscribeWithSelector — 선택 구독 + 이전값 + fireImmediately.

이 넷을 겹쳐 쓰는 게 표준형: create<S>()(devtools(persist(…))).

테스트 — RNTL까지 공식 지원

웹 RTL + RN은 RNTL(Native Testing Library) + MSW. store mock으로 테스트마다 setState(initial, true) 리셋 — Jest·Vitest 레시피가 공식 문서에 전문 수록. 행위 테스트 원칙(구현상세 금지)은 BP와 동일.

React Native 적용 (오해 주의 2건 수정됨)

  • RN·웹·바닐라 동일 API. createStore(vanilla)는 React 밖 순수 JS/TS 런타임(이벤트 리스너·서비스·테스트)용 — OS 네이티브 코드(Swift/Kotlin)와 메모리를 공유하는 수단이 아니다.
  • persist 저장소만 AsyncStorage 어댑터로 교체. 단 AsyncStorage는 비동기(웹 localStorage는 동기)라 앱 시작 시 하이드레이션 대기(스플래시·완료 확인) 없이 쓰면 초기 화면 깜빡임·초기값 덮어쓰기가 난다.
  • FSD model/ 세그먼트가 slice 자리. 토큰 저장은 expo-secure-store 등 OS 암호화 저장소 (BP 보안 섹션 참조).
